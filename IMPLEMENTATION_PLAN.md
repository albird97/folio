# Folio implementation plan

Folio is one PDF product with three targets: a macOS app, a Windows app (both Tauri 2) and a
Chrome extension (Manifest V3). Document logic is written once in shared packages; each target
contributes only a thin platform adapter and its own shell.

- **Status:** Phases 1–6 are complete; Phase 7 (Release quality) is under way. See
  [Phase 6 and 7 results](#phase-6-and-7-results), [Phase 4 and 5 results](#phase-4-and-5-results),
  [Phase 3 results](#phase-3-results), [Phase 2 results](#phase-2-results) and
  [Phase 1 results](#phase-1-results).
- **What works where:** [PLATFORM_CAPABILITIES.md](PLATFORM_CAPABILITIES.md) (generated, tested).
- **How to build and run:** [README.md](README.md).

## 2. Architecture

```
apps/
  desktop/            Tauri 2 shell: Vite + React UI, Rust commands (src-tauri/)
  chrome-extension/   MV3: popup, side panel, editor page, options, service worker
packages/
  document-model/     Types, branded IDs, operations, undo/redo history, recovery snapshots
  pdf-core/           PDF.js engine wrapper, errors, sniffing, hashing, Vite asset plugin
  platform-adapters/  Adapter contract, web/memory adapters, capability matrix
  shared-ui/          Design tokens, Tailwind v4 theme, primitives, icons, brand mark
  editor/             The shared workspace UI and its Zustand stores
tests/
  fixtures/           Real PDFs (pdf-lib + qpdf), regenerated by scripts/generate-fixtures.ts
  e2e/                Playwright: extension/ (unpacked in Chromium), desktop-web/ (UI in Chromium)
  desktop/            WebDriver test of the real desktop binary (tauri-driver)
```

Dependency direction is strictly downward:

```
apps/desktop ─┐                        ┌─ document-model (no DOM, no platform APIs)
              ├─ editor ─┬─ pdf-core ──┤
apps/chrome ──┘          ├─ platform-adapters ─ document-model
                         └─ shared-ui
```

Internal packages are consumed as TypeScript source (`exports` point at `src/`), so there is no
package build step. Vite bundles them per target.

### 2.1 Platform adapters

`PlatformAdapter` (packages/platform-adapters/src/types.ts) is the only way shared code touches
the platform:

| Concern        | Desktop (Tauri)                                              | Chrome extension                         | Web (dev/tests)       |
| -------------- | ------------------------------------------------------------ | ---------------------------------------- | --------------------- |
| Pick files     | Native dialog shown **by Rust**                              | `<input type=file>` in a page            | `<input type=file>`   |
| Incoming files | Drag and drop, launch arguments, Finder events → Rust grants | Side panel → editor hand-off (IndexedDB) | `deliverFiles()`      |
| File reads     | `read_granted_file(token)` → binary IPC                      | `File.arrayBuffer()`                     | `File.arrayBuffer()`  |
| Storage        | `localStorage`                                               | `chrome.storage.local` (+ change events) | `localStorage`        |
| Commands       | Native menu events and keyboard                              | Keyboard only                            | Keyboard only         |
| Clipboard      | `navigator.clipboard`                                        | `navigator.clipboard`                    | `navigator.clipboard` |

Each adapter declares `RuntimeFeatures`. Tests assert those flags agree with the capability matrix
for the matching target (`runtimeMismatches`), so the documentation cannot silently drift from the
code.

### 2.2 Document model

- **IDs:** `doc_`, `src_`, `page_`, `annot_`, `field_`, `asset_` and `op_` prefixes, plus 96 random bits, branded per type.
- **`DocumentModel`:** sources, page order, page sizes and rotation, metadata, annotations
  (markup, notes, ink, shapes, added text, added images, signatures), form fields, assets and export settings.
  Page sizes are in points with /UserUnit applied; each page keeps its `userUnit`, because
  annotation geometry is stored in unscaled PDF user space.
- **`DocumentViewState`:** current page and zoom. This is UI state, deliberately kept outside the
  model and outside undo history.
- **Operations:** `pages/rotate|reorder|insert|remove`, `metadata/update`,
  `annotations/add|replace|remove`, `forms/set-values`, `stamps/set`, `text-layers/set` and
  `batch`. Applying an operation is pure and returns its
  inverse, so undo and redo are exact.
- **History:** undo and redo stacks of `{operation, inverse}`, with a size limit and coalescing
  (e.g. dragging an annotation, typing a title). Dirty state compares the top of the history with
  a saved marker, so it stays correct across undo and redo.
- **PDF bytes:** never stored in the model or the history. Sources are referenced by ID and SHA-256;
  bytes live once in each target's resource registry.
- **Recovery snapshots:** JSON that is version-tagged, validated with zod, checked for internal
  consistency and never echoes content in its errors. Fields added in Phase 6 (stamps, recognized
  text) have defaults, so older snapshots still load.
- **Phase 6 content:** form field values (fields come from the opened file; their widgets are read
  from it when shown), page numbers and a watermark (`model.stamps`, laid out once in
  `stamp-layout.ts` for the page view and the file), and recognized text per source page
  (`model.textLayers`, the words in a JSON asset validated on read). Copies of a page share its
  recognized text, because it belongs to the page's image.

“Added text” is new content placed on a page. It is never presented as editing the PDF's
existing text objects (see [§4](#4-pdf-engines-and-licensing)).

### 2.3 Security model

**Desktop**

- The webview has no filesystem plugin. A path becomes readable only after the user picks it,
  drops it or launches Folio with it. Rust then registers it under a random 128-bit token, and
  commands accept tokens, never paths. A compromised webview (for example, a malicious PDF
  exploiting the renderer) can read only files the user already opened.
- Folio's own events and commands carry tokens and file names, never paths. Drag hover is a plain
  `true`/`false` (`folio://drag-hover`), which Rust emits from the window's drag events, so the
  UI does not listen to Tauri's `tauri://drag-*` events, which carry the paths of everything
  dragged over the window. `core:event:allow-listen` cannot be scoped by event name, so a
  compromised page could still subscribe to those built-in events and learn such paths; it still
  cannot read a file it was not granted.
- Nothing is dropped silently. Rust applies the same name rule as the workspace
  (`isLikelyPdfName`): only a name ending in `.` plus 1–8 ASCII letters or digits other than `pdf`
  counts as “not a PDF”; any other name (no extension, or one like `.v2_final`) is granted and
  checked by content. Files that are not PDFs and files that vanished before they could be granted
  come back by name and appear as a notice or an error tab.
- App commands have generated `allow-*` permissions. The `main` capability grants only those five
  commands plus `event:listen/unlisten`, `window:set-title`, `window:start-dragging` and
  `window:internal-toggle-maximize`. The tab strip is a window drag region, which the macOS
  overlay title bar relies on: drag it to move the window, double-click it to zoom or maximize.
- The CSP permits `'self'`, `ipc:`, `blob:`/`data:` images and `'wasm-unsafe-eval'` (needed for
  PDF.js image decoders), and nothing remote. The tauri-driver test asserts zero CSP violations.
- IPC errors are `{code, message}` with no paths.
- **Exports that are not PDFs** (page images, ZIP archives of them, text) go through
  `save_file_as`, which checks that the data is what its kind claims (PNG, JPEG, ZIP, UTF-8 text)
  before the save dialog appears; such files are never granted or listed as recent.
- **Ask Claude (opt-in)** keeps the user's Anthropic API key in the OS credential store (keyring),
  which the webview cannot read. The webview's SDK sends requests through `ai_request`, which only
  reaches `POST https://api.anthropic.com/v1/messages` and `/count_tokens`, allows only the
  `anthropic-version`, `anthropic-beta` and `content-type` headers, adds the key, caps bodies at
  32 MB and streams answers back on a channel. The CSP still allows no remote connections.
- **Updates (opt-in)** are checked, verified and installed entirely in Rust (native menus and
  dialogs); the webview has no updater permission. An update must be signed with Folio's key for
  the version the feed announces, and unsaved work is asked about before Folio restarts.
- **Fuzzing:** property tests (proptest) feed arbitrary input to everything that parses data from
  the webview, Chrome or disk: native messaging frames and messages, file names, recovery ids,
  recent files, grant tokens, launch arguments, settings files.
- **Save** writes only through a grant token, with the SHA-256 Folio last read or wrote: a file
  changed by another program is not overwritten unless the user confirms. Writes go to a private
  temporary file in the same folder, are checked again just before an atomic replace
  (`ReplaceFileW` on Windows), and keep the target's permissions. **Save As** returns a new token
  only when asked to keep access. A backup `ReplaceFileW` leaves that cannot be deleted right away
  is retried, then marked disposable; later saves into the folder delete Folio's own leftovers
  (exact `.folio-<uuid>.tmp`/`.bak` names, regular files only, never links) once they are an hour
  old, but never a previous version Folio had to keep.
- **Recovery, recent files and transfers** live in Folio's data folder (only the user can open
  it). Record ids and file keys are generated by Folio and checked against a strict pattern
  (including Windows device names); nothing in the folder is addressed by a path from the webview.
- **Native messaging host** (the desktop binary started by Chrome with the caller's origin): only
  the official extension id is answered; messages are length-prefixed JSON objects of at most
  12 MiB, parsed into fixed types (`hello`, `begin`, `chunk`, `end`); documents must be PDFs of
  at most 512 MB, arrive in order and match their announced size and SHA-256; no more than three
  may wait or arrive, checked under a lock shared by all host processes together with the free
  disk space; they are spooled in the data folder and the app asks the user before opening one.
  Paths inside the data folder are never opened as documents. Nothing runs a shell.
- **Registration with Chrome** is a native menu action (File → Connect to Chrome…) with a native
  confirmation whose default is Cancel; the webview cannot register anything. Only the official
  extension id is registered and answered, and a copy of Folio that others could replace refuses
  to register itself, saying why and where to move it: the temporary folder, removable volumes
  and disk images, App Translocation; on Unix any owner other than root or the user on the way to
  the program, folders writable by everyone or by a group other than root's or the user's private
  group (unless sticky and above the program's own folder), a program writable by others; on
  Windows network shares, drives that are not fixed disks, and access lists that let Everyone,
  Users or Authenticated Users write to the program or a folder above it. The manifest names the
  canonical path that was checked (without the `\\?\` prefix on Windows).
- **Several copies of Folio** share the data folder (macOS allows several; on Windows and Linux
  the single-instance plugin may lose a race). Every running copy holds a shared lock on
  `instance.lock`; only a copy that can take it exclusively at startup (retrying for 1.5 s, and
  taking turns through `instance.gate`, since turning the lock shared is not atomic everywhere)
  deletes accepted transfers, abandoned recovery records and offers waiting transfers. On Windows
  and Linux only the process the plugin keeps takes the lock, in `setup`.
- **Startup** never touches the files in the recent list (an offline network share could hang it);
  stored paths are checked as stored, and where a path really leads is checked when it is opened.

**Extension**

- Install-time permissions are `storage`, `sidePanel`, `activeTab` and `scripting` (no warnings).
  `downloads`, `nativeMessaging` and site access (`https://*/*`, `http://*/*` as optional host
  permissions, one site at a time) are requested when a feature first needs them; the options page
  lists what was granted and removes it. There are no content scripts, and
  `externally_connectable` is not set. Tests check both the manifest and
  `chrome.permissions.getAll()`.
- The popup never requests a permission (Chrome closes popups when a prompt opens); the editor tab
  and the side panel do, straight from a click.
- The manifest CSP is `default-src 'self'` with `script-src 'self' 'wasm-unsafe-eval'`, images
  from `'self'`, `blob:` and `data:`, fonts from `'self'` and `data:`, and inline styles (React
  style props) but no inline scripts. Its `connect-src` allows `https:` and `http:` only so the
  service worker can download PDFs the user asked to open; every extension page adds its own
  `connect-src 'self'` policy, so pages cannot send requests, beacons or images to other servers.
  Unit tests pin both policies; an e2e test checks that the editor's requests to other origins are
  blocked.
- Downloads run only in the service worker, over a port, from sites the user allowed: no referrer,
  no cookies unless the user agrees for one request after a site answers with a sign-in page, a
  256 MB cap, and the PDF header checked before the bytes are handed over (single-use hand-off).
  Web addresses travel from the popup to the editor through session storage, not the tab URL.
- Scripts run in a tab only after a click on Folio's toolbar button there (`activeTab`): one lists
  the PDF links on the page, the other opens Chrome's print dialog. Their results are validated.
- The service worker validates every message with zod, caps message size and accepts only this
  extension's pages as senders. It holds no state in memory beyond a queue that orders
  activity-log writes.
- Documents never leave the device unless the user turns on Ask Claude and asks a question. Its
  key lives in `chrome.storage.local` (never synced) and only the service worker uses it and talks
  to `api.anthropic.com` (access requested from a click; removing it forgets the key); pages keep
  `connect-src 'self'`. An e2e test asserts no network requests while opening a document. Activity stores counts by default; file names only on opt-in, and turning that off
  erases stored names.
- Side panel → editor hand-offs are single-use IndexedDB records. Reading one deletes it, a record
  older than 10 minutes is ignored, and expired records are purged on every hand-off written or
  read, when the browser starts and when the extension is installed or updated. Folio sets no
  timer, because that would need the `alarms` permission. If the editor cannot be opened after
  the record is written, the side panel deletes the record and shows an error.

## 3. Technology decisions

| Area          | Choice                                                                             | Why                                                                                                                                              |
| ------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Desktop shell | Tauri 2                                                                            | Small installers, Rust for privileged work, a fine-grained capability system.                                                                    |
| UI            | React 19, TypeScript 6, Tailwind CSS 4, Radix primitives (shadcn-style components) | Shared across all surfaces.                                                                                                                      |
| State         | Zustand 5                                                                          | Document state (`createWorkspaceStore`) and UI state (`createUiStore`) are separate stores.                                                      |
| Rendering     | PDF.js 6, **legacy build**                                                         | The modern build calls `Map#getOrInsertComputed` and `Math.sumPrecise` natively, which macOS 13–15 WebKit lacks. The legacy build is polyfilled. |
| PDF.js assets | Bundled per target (`pdfjsAssets()` Vite plugin)                                   | CMaps, standard fonts, ICC profiles and WASM decoders load from the app's own origin. MV3 forbids remote code.                                   |
| Tests         | Vitest 5, Playwright 1.56, axe-core, `cargo test`, tauri-driver                    |                                                                                                                                                  |
| Icons         | Lucide (ISC)                                                                       | 16px at 1.75 stroke in toolbars, 14px in dense rows, 20px in empty states.                                                                       |
| Typeface      | Inter Variable (OFL), bundled                                                      | Works offline in the extension.                                                                                                                  |

### Design system

**Restrained:** neutrals tinted toward a petrol-ink hue, plus one accent used only for primary
actions, selection and focus. All tokens are OKLCH, in light and dark themes, and axe checks text
contrast in both. Pages stay white in dark mode because documents should look like documents. The
desktop UI uses a 13px base, like native apps. The extension's popup and side panel are designed
for their space rather than shrunk from the desktop layout; the extension editor page reuses the
full workspace.

## 5. Phases

Status legend: ✅ done · 🔜 next · ⏳ later.

### Phase 1: Foundation ✅

- [x] Inspect the repository and environment.
- [x] Monorepo (pnpm workspaces, root Cargo workspace), TypeScript strict mode, ESLint (+ jsx-a11y,
      react-hooks), Prettier and Vitest projects.
- [x] Shared core: document model, operations, history, recovery format; PDF engine; adapter
      contract and capability matrix.
- [x] Design system: tokens, theme, primitives, brand mark, app and extension icons (original art).
- [x] Desktop shell: token-based file grants, native menus, drag and drop, launch arguments and
      Finder events, strict capability and CSP, a file association for `.pdf`, bundle metadata.
- [x] Extension shell: popup, side panel, editor page, options, service worker, validated
      messaging, IndexedDB hand-off, activity log with privacy controls.
- [x] Shared workspace vertical slice on both targets: open (picker, drop, launch, hand-off), unlock
      password-protected files, tabs, pages list, single-page preview of the selected page,
      properties, errors, themes and shortcuts.
- [x] Real fixtures and unit, Rust, Playwright (extension and desktop UI, with axe) and native
      tauri-driver tests.
- [x] CI: checks, Linux build and native e2e on every push. macOS and Windows installers run on
      main, tags, PRs, on demand, or with `[desktop]` in a commit message.

### Phase 2: Shared PDF viewer ✅

- [x] A continuous, virtualized page viewer (`packages/editor/src/viewer`). Only pages near the
      window are mounted; one render queue (`RenderScheduler`) orders work by distance from the
      window and drops it when pages scroll away; rendered canvases are cached per zoom,
      rotation and devicePixelRatio within a 40-megapixel budget (`CanvasCache`), visible ones
      pinned; the previous zoom's canvas stays on screen, stretched, until the new one is ready.
- [x] Lazy page sizes: the first 64 pages are read before a document opens and the rest in the
      background (or on demand when a page is shown). Estimates are corrected as pages are read,
      with the view anchored so nothing jumps.
- [x] Thumbnails in a sidebar tab. They are virtualized by arithmetic (every slot has the same
      height) rather than with IntersectionObserver, which made scrolling and keyboard focus
      simpler; a page already rendered in the viewer is downscaled instead of drawn again.
- [x] Zoom (automatic, fit width, fit page, presets, ⌘/Ctrl +/−/0, Ctrl+wheel steps, smooth
      trackpad and touch pinch, WebKit gesture events) anchored at the pointer or the middle of
      the window, and view rotation, all stored in `DocumentViewState`.
- [x] The PDF.js text layer for selection and copying; search with highlights (text extracted in
      the PDF.js worker, accent- and case-insensitive by default, whole words, matches across
      separately drawn runs, progressive results, a results list in the sidebar, ⌘/Ctrl F, ⌘G/F3).
- [x] Save a copy of the original file: on desktop a `save_pdf_as` command shows the native save
      dialog, accepts only PDF data and writes through a temporary file; in browsers a download.
- [x] Bookmarks: explicit and named destinations, shown as a WAI-ARIA tree.
- [x] Tests: a 1,500-page performance budget (time to first page, mounted pages, canvases, DOM
      size, JS heap), search accuracy on fixtures, keyboard navigation, zoom anchoring, outline
      destinations, text selection and copying, byte-identical saved copies, axe in both themes,
      and WebKitGTK checks of the text layer, highlights and the save command in the real binary.

### Phase 3: Core editing ✅

- [x] Annotation layer (pointer events, not HTML5 drag and drop, because Tauri's native drop
      handling disables DOM drag and drop on Windows): highlight, underline and strikethrough
      from text selection; notes; ink; shapes (rectangle, ellipse, line, arrow); added text;
      added images. Select, move, resize, nudge and delete, all through model operations and
      history (⌘/Ctrl Z, ⇧⌘Z / Ctrl Y), with an inspector and a Comments list.
- [x] Shared layout: annotation geometry and the added-text layout (standard-font metrics,
      wrapping, baselines) live in `document-model`, so the SVG on screen and the appearance
      streams in the file agree. Text and images added to a turned page read level.
- [x] Page management UI: multi-select, rotate, delete, duplicate, extract, reorder (thumbnail
      drag via pointer events), insert blank pages or pages from another PDF (password prompt
      for protected files), merge and split into new tabs. A document can combine several
      source files; search, thumbnails and bookmarks follow pages as they move.
- [x] `pdf-core/export`: writes the model to a new PDF with @cantoo/pdf-lib, as editable
      annotations with appearance streams or flattened. Pages are copied without dragging in the
      pages they link to; removed pages leave no content, annotations or form values behind;
      protected documents stay protected with the same password and permissions. Integrity
      tests re-open every export with PDF.js and run `qpdf --check` (installed on CI).
- [x] Metadata editing in the properties panel (Info dictionary and XMP kept consistent).
- [x] Permission flags (comment, assemble, modify, copy) are honoured and explained.
- [x] Save as (download in browsers, native dialog on desktop), with editable or flattened
      comments; closing a changed document asks first.

### Phase 4: Desktop integration ✅

- [x] Save: written back through the file grant, atomically (private temp file, re-check, atomic
      replace), refusing files changed on disk unless the user confirms, falling back to Save As
      for files that cannot be written. Save As can keep access to the new file for later saves.
      The source is never overwritten without an explicit save.
- [x] Printing: the chosen pages are written to an in-memory PDF (comments flattened or left out),
      drawn at print resolution and laid out for the system print dialog; pages turn to fit the
      paper. Respects the print permission.
- [x] Autosave and crash recovery: snapshots, original files and images in the app data folder
      (IndexedDB in the extension), written two seconds after a change, offered on restart with
      Restore and Discard, and deleted as soon as work is saved, undone, closed or discarded.
- [x] Single instance on Windows and Linux (`tauri-plugin-single-instance`); macOS relies on
      Finder's open events. Remembered window state.
- [x] Shortcuts for Save and Print, single-key tool shortcuts, copy/cut/paste of comments and
      pasting images, recent files (start screen and File → Open Recent), a close guard.
- [ ] Verify the native integrations on a real Mac and a real Windows PC. The capability matrix
      rates them Limited until then.
- [ ] Signed and notarized installers, once credentials exist (see README).

### Phase 5: Chrome integration ✅

- [x] Open the PDF in the current tab: `activeTab` from the toolbar click, then a new editor tab
      asks for access to the site (optional host permission) and downloads it in the service
      worker. Inaccessible pages and URLs are explained; sign-in pages lead to a consent step
      before the user's cookies are sent.
- [x] Open a PDF from a web address in the editor; list the PDFs a page links to in the side
      panel to open or download (`downloads` requested on first use).
- [x] Save the current page as PDF through Chrome's print dialog.
- [x] Side panel tools: rotate, extract pages, pages to PNG/JPEG (ZIP for several), extract text.
- [x] Native messaging host `io.github.albird97.folio` (the desktop binary): origin allowlist,
      typed messages with size limits, spool limits, a prompt in the desktop app before opening,
      a clear message when the app is absent, registration from the desktop app's menu and by
      hand (README).

### Phase 6: Advanced tools ✅

- [x] Forms: AcroForm fields filled on the page (text, multi-line, comb, password, check boxes,
      radio buttons, drop-down and list boxes) through `forms/set-values`; PDF.js draws them from
      its annotation storage and writes them as an incremental update (appearances generated,
      encryption kept); "Save with form flattened" draws them into the pages, per page, so
      duplicated pages and pages from other files work too. XFA forms are reported, not filled.
- [x] Signatures: drawn (pointer events, smoothed, pen pressure), typed in a bundled OFL
      handwriting font or imported (paper made transparent, cropped to the ink); placed with a
      click or into a signature field; saved as Stamp annotations or flattened; optionally
      remembered on the device (at most five, checked on read). Not cryptographic signing.
- [x] OCR: Tesseract.js 7 (LSTM) with bundled English, Indonesian and Chinese models, one page at
      a time on the device; recognized words are searchable, selectable and copyable, and saved as
      invisible text with a glyph-less Unicode font (Type0/Identity-H, ToUnicode), so every
      script extracts correctly.
- [x] Page numbers and watermarks: one layout for the page view and the file, placed on the page
      as shown; drawn into saved and printed pages as pagination artifacts, numbered by position
      in the whole document (also in extracts, split parts and printed ranges).
- [x] Export pages as images (PNG/JPEG, several in a ZIP) and text (including recognized text) in
      the editor on every target, through a Rust `save_file_as` that checks the data on desktop.
- [x] Reduce file size: lossless (streams, thumbnails) or JPEG re-encoding of large images to 2000
      or 1400 px, keeping every image whose new version is not smaller.
- [x] Password protection (AES-256): a password to open, restrictions with an optional permissions
      password, or removal for documents opened with their password and without restrictions;
      each copy is re-opened with PDF.js before it is saved.
- [x] Ask Claude (opt-in, the user's own Anthropic API key): summarize and ask about a document
      with streamed answers that cite pages; disclosed and consented, nothing sent until the user
      asks; the official TypeScript SDK with platform transports that add the key outside the page
      (a Rust proxy on desktop, the service worker in Chrome).

## 7. Known limitations

- **Rendering at high zoom:** each page is drawn into one canvas of at most 16.7 megapixels, so at
  very high zoom on high-density screens pages are drawn at a lower resolution and look soft.
  Tiled rendering of the visible part would fix this.
- **Text layer:** it is measured once per page and orientation and then scaled with CSS, so
  selections can drift slightly from the drawn text at zoom levels far from the first one.
- **Interactive PDF content:** link annotations are drawn but not clickable, and bookmarks that
  point to websites or other files are listed but not followed.
- **Forms:** XFA forms (also hybrid AcroForm+XFA ones) are shown as saved but cannot be filled in;
  form scripts (calculations, formatting, validation) do not run; characters a field's font
  cannot show come out as "?" in flattened or printed copies; list boxes lose their border once an
  option is chosen (PDF.js draws them that way); check boxes sharing one name tick together;
  fields on pages inserted from other files stay as drawn.
- **Signatures** are pictures: a signature field stays unsigned, and remembered signatures are
  stored unencrypted on the device. Typed names outside the font's Latin, Latin Extended and
  Vietnamese letters use the system's handwriting font.
- **Page numbers and watermarks:** one line of text in the standard PDF fonts, one of each per
  document; numbers are positions, not page labels. A watermark under the content is hidden by
  pages that paint their whole area (such as scans), although the page view still shows it.
- **OCR:** English, Indonesian and Chinese only; pages must show their text upright (no vertical or
  right-to-left text); cancelling discards the whole run; it adds about 19.4 MB to each app.
- **Ask Claude:** answers are plain text; conversations are lost on reload; desktop requests do not
  use proxy settings from the OS.
- **Reduce file size:** gray images become RGB JPEGs; the size is compared with the opened file,
  so a document with many additions may read "already as small as Folio can make it".
- **Updates:** checked only at startup; no download progress; the feed is this repository's GitHub
  releases, which users cannot reach while the repository is private.
- **Page labels:** page numbers are physical positions; `/PageLabels` (such as roman numerals for
  front matter) are not shown yet. Saved files keep page labels only while the original pages keep
  their positions; after reordering or deleting pages they are dropped rather than left wrong.
- **Editing limits:** added text uses the standard PDF fonts, so characters outside Windows-1252
  (such as Chinese or emoji) are saved as "?" (Folio warns). Form fields and tagged structure on
  pages copied from other files are kept as drawn but not merged into the document's form or
  structure tree. Changing a signed document invalidates its signatures (Folio says so when
  saving).
- **Search:** scanned pages have no text until Tools › Recognize text; right-to-left and vertical
  text are untested; results stop at 10,000 matches (the find bar says so).
- **macOS and Windows:** the native dialogs, drag and drop, menus, shortcuts, file association,
  Save, printing, recovery, recent files, single instance and native messaging are built in CI
  and tested on Linux, but have not been tried on a real Mac or Windows PC.
- **Printing** sends pages as images (150 dpi up to 100 pages, 110 up to 300, 72 beyond), so
  printed text is not vector text.
- **Recovery data is not encrypted.** The comments and edits of a password-protected document are
  stored readable in Folio's data folder (or the extension's storage) until it is saved, closed or
  discarded; the original file stays encrypted.
- **Extension:** it cannot be the system PDF handler, cannot script Chrome's built-in PDF viewer,
  and cannot read PDFs opened from the computer (`file://`) or scripts on Chrome's own pages and
  the Web Store. PDFs from the web are capped at 256 MB, and sites that need more than cookies
  (HTTP authentication prompts, tokens in headers) cannot be opened. The page-to-image tool keeps
  images in memory and takes up to 300 pages at a time.
- **Native messaging:** registered for Google Chrome and Chromium only (not Edge, Brave and other
  Chromium browsers). The extension uses a development key until it is published; any unpacked
  extension with the same public key gets the same id (transfers are still confirmed).
- **Export pages as images** keeps the images in memory and takes up to 300 pages at a time.
- **macOS 13.3+:** required. Tailwind CSS 4 needs Safari 16.4-level WebKit.
- **Dependency pins:** ESLint 9 (end of life) is pinned until `eslint-plugin-jsx-a11y` supports
  ESLint 10.
